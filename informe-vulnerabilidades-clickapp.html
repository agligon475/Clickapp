Vulnerabilidad Crítica #1

Account Takeover sin Autenticación en `api/auth.js`

CVE-Equivalent: IDOR / Broken Authentication (CVSS Score: 9.8 — CRITICAL)

Mecánica de la Falla

En el endpoint /api/auth.js (línea 146), la acción reset_password acepta un store_id y una new_password sin requerir ningún token de verificación previo, token OTP firmado por email ni sesión activa.

Impacto en el Negocio:
  • Cualquier atacante que conozca el subdominio o store_id público de un comercio puede cambiar su contraseña arbitrariamente.
  • Pérdida total de control del catálogo, WhatsApp y datos comerciales de los clientes.
Remediación & Código Recomendado
- // Código vulnerable: cambia clave sin validar token - if (action === 'reset_password') { ... patchDb(new_password) } + // Solución defensiva: Validar OTP criptográfico con expiración + const { reset_token, new_password } = req.body; + const payload = verifyResetToken(reset_token); // HMAC-SHA256 + if (!payload || payload.store_id !== actualStoreId) { + return res.status(403).json({ error: 'Token inválido o expirado' }); + }
Implementar tokens de un solo uso (OTP o JWT efímero de 15 min) generados al solicitar la recuperación en forgot_password.

Vulnerabilidad Crítica #2

Tokens de Sesión Forjables en Base64 (Sin Firma Criptográfica)

CVE-Equivalent: Cryptographic Failure / Broken Object Authorization (CVSS Score: 9.1 — CRITICAL)

Descripción del Problema

En /api/auth.js (línea 98), el token de sesión devuelto al usuario tras autenticarse se genera de forma trivial:

const sessionToken = Buffer.from( `${actualStoreId}:${Date.now()}:authenticated` ).toString('base64');
  • El token no cuenta con firma HMAC, secret key ni integridad garantizada.
  • Cualquier usuario puede codificar en Base64 el nombre de cualquier tienda y suplantar la sesión del merchant.
Parche & Firma Criptográfica
+ import jwt from 'jsonwebtoken'; + const JWT_SECRET = process.env.AUTH_JWT_SECRET; + const sessionToken = jwt.sign( + { store_id: actualStoreId, role: 'merchant' }, + JWT_SECRET, + { expiresIn: '7d' } + );

Al migrar a JWT firmado con AUTH_JWT_SECRET, ningún actor malicioso puede forjar identificadores ni escalar privilegios entre tiendas.

Vulnerabilidad Alta #5

Manipulación Pública de Comprobantes y Planes

CVE-Equivalent: Insecure Direct Object Reference / State Tampering (CVSS Score: 7.2 — HIGH)

Inyección en `submit_payment_receipt`

En /api/super-admin.js (línea 72), la acción pública submit_payment_receipt permite actualizar billing_info, upgrade_requested y cambiar el estado payment_status a 'receipt_submitted' de cualquier tienda sin validar si el emisor es el dueño real del comercio.

  • Un usuario malintencionado puede forzar cambios de estado y adjuntar URLs arbitrarias a comercios competidores.
Corrección Estructural
  • Validación de Dominio/Token: Exigir que la subida del comprobante provenga de la sesión autenticada del Dashboard o de un token único temporal enviado por correo.
  • Sanitización de URLs: Validar que receipt_url pertenezca estrictamente al dominio de Cloudinary verificado (https://res.cloudinary.com/daletepido/...) para evitar SSRF o phishing.

Patrón de Token HMAC & Verificación Centralizada

Código reutilizable para implementar en la suite de Serverless Functions | DATA DE UPDATE: 08/10/2026 — 19:30 hs

Módulo de Seguridad Central (`api/helper.js`)
import crypto from 'node:crypto'; const JWT_SECRET = process.env.AUTH_JWT_SECRET || 'SECRET_OBLIGATORIO_EN_ENV'; export function signToken(payload, expiresInSeconds = 86400 * 7) { const header = Buffer.from(JSON.stringify({ alg: 'HS256', typ: 'JWT' })).toString('base64url'); const exp = Math.floor(Date.now() / 1000) + expiresInSeconds; const body = Buffer.from(JSON.stringify({ ...payload, exp })).toString('base64url'); const signature = crypto.createHmac('sha256', JWT_SECRET).update(`${header}.${body}`).digest('base64url'); return `${header}.${body}.${signature}`; } export function verifyToken(token) { if (!token || !token.includes('.')) return null; const [h, b, sig] = token.split('.'); const expectedSig = crypto.createHmac('sha256', JWT_SECRET).update(`${h}.${b}`).digest('base64url'); if (!crypto.timingSafeEqual(Buffer.from(sig), Buffer.from(expectedSig))) return null; const payload = JSON.parse(Buffer.from(b, 'base64url').toString('utf8')); if (payload.exp < Math.floor(Date.now() / 1000)) return null; return payload; }
Beneficios Directos de este Helper
  • Zero External Dependencies: Utiliza el módulo nativo node:crypto con soporte base64url (RFC 7519).
  • Protección contra Timing Attacks: Usa crypto.timingSafeEqual para evitar ataques de tiempo al comparar firmas.
  • Expiración Forzada: Invalida automáticamente sesiones antiguas de forma nativa sin consultas adicionales a la base de datos.
